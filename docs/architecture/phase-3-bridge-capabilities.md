# Phase 3: Bridge Capabilities Specification

## 1. Method and scope
This document was generated by cross-referencing the current implementation of the FastAPI application (`app/modules/`), the existing PHP integration bridge (`bridge/plugin.php` and `bridge/handlers/`), and the documented capabilities of osTicket (`notes/OSTICKET_CAPABILITIES.md`).
The goal is to perform a gap analysis identifying the specific commands, events, and read-through queries that the PHP bridge must implement to fulfill the promises of the FastAPI endpoints.

## 3. Required commands — full specification

### Organizations (`org.*`)
*   **`org.create`**:
    *   **Native method**: `Organization::fromVars()` or `Organization::create()`
    *   **Payload**: `name` (string, required), `manager_id` (int, optional), `notes` (string, optional)
    *   **Permissions**: `PERM_ORG` or agent-level directory permissions.
    *   **Result**: `{'org_id': <int>}`
*   **`org.update`**:
    *   **Native method**: `$org->update()`
    *   **Payload**: Same as create (optional fields).
*   **`org.delete`**:
    *   **Native method**: `$org->delete()`

### Knowledgebase (`kb.*`)
*   **`kb.category.create` / `kb.faq.create` / `kb.canned.create`**:
    *   **Native methods**: `Category::create()`, `FAQ::create()`, `Canned::create()`
    *   **Permissions**: `PERM_FAQ` / `PERM_CANNED`

### Banlist (`banlist.*`)
*   **`banlist.create`**:
    *   **Native method**: `Banlist::add()`
    *   **Permissions**: Admin-level / `PERM_BANLIST`
    *   **Payload**: `email` (string, required)

### Forms (`form.*`)
*   **`form.create`**:
    *   **Native method**: `DynamicForm::create()`
    *   **Payload**: `title` (string), `instructions` (string)

### Departments & Teams (`dept.*`, `team.*`)
*   **`dept.create`**: `Dept::create()`
*   **`team.create`**: `Team::create()`

*   `dept.created`, `team.created`

## 5. Required read-through operations
All reads are actively fulfilled by `app/integration/osticket/read_repository.py`.
Current reads implemented: Tickets, Users, Organizations, Staff, Teams, Departments, Help Topics, SLAs, Priorities, KB Categories, FAQs, Canned Responses, Banlist, Forms, Commands, Global Search.

## 6. Gaps requiring a decision, not just an implementation
Currently, osTicket natively handles Banlist additions via simple static DB insertions rather than a rich ORM lifecycle (varies by version). We must confirm that `Banlist::add()` exists in `v1.18.1` or fallback to direct SQL insertion inside the bridge.
